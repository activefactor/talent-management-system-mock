# タレントマネジメントシステム 要件定義書

**バージョン**: 1.0.0
**作成日**: 2026-04-17
**対象**: 社内エンジニア向けタレントマネジメントシステム

---

## 1. プロジェクト概要

### 1.1 背景・目的

社内エンジニアのスキルや特性を可視化し、以下の課題を解決する社内向けWebシステムを構築する。

| 対象ユーザー | 課題 | 解決したいこと |
|---|---|---|
| 管理者 | どのスキルを持った人材がいるか把握できていない | スキルマップ・人材検索の提供 |
| 若手エンジニア | 同じ興味・技術領域を持つ社員を知る機会がない | 共通興味の可視化・交流のきっかけ作り |
| シニアエンジニア | 若手から相談を受けやすい状態を作れていない | 専門領域・相談受付状況の公開 |
| 全エンジニア | 日々の努力が見えにくく、モチベーション維持が難しい | 学習ログとバッジによる可視化・自己効力感の向上 |

### 1.2 システム名称

**TalentHub**（仮称）

## 2. ユーザー定義

### 2.1 ユーザーロール

| ロール | 説明 |
|---|---|
| `admin` | 管理者。全ユーザー情報の閲覧・編集、マスターデータ管理が可能 |
| `senior` | シニアエンジニア。自プロフィール管理、相談受付設定、若手への公開情報設定が可能 |
| `engineer` | 一般エンジニア（若手含む）。自プロフィール管理、他ユーザーの公開情報閲覧が可能 |

### 3.3 パーソナリティ情報（任意登録）

本セクションの情報は**ユーザーが任意で登録**する。未登録でも他機能の利用に支障はない。
公開範囲はユーザー自身が設定できる（全体公開 / ロール限定 / 非公開）。

#### 3.3.1 ストレングスファインダー（CliftonStrengths）

- TOP5 の資質を登録（テキスト入力 or プルダウン選択）
- 登録されている場合、プロフィールページに資質タグを表示
- **分析表示**（第1フェーズは表示のみ）:
  - 34資質を「実行力 / 影響力 / 人間関係構築力 / 戦略的思考力」の4領域に分類し、レーダーチャートで可視化
  - TOP5から導く「強みの傾向コメント」（静的テキストでの定型文表示）

#### 3.3.2 MBTI 診断

- 16タイプをプルダウンで選択（INTJ / ENFP など）
- 登録されている場合、プロフィールページにMBTIタイプバッジを表示
- **分析表示**（第1フェーズは表示のみ）:
  - 4軸（E/I, S/N, T/F, J/P）のバーグラフ表示
  - タイプ別の特徴サマリーテキスト表示

#### 3.3.3 ストレングスファインダー × MBTI 複合分析

- 両方登録済みの場合に表示
- 「コミュニケーション傾向」「学習スタイル」「チームでの役割」などの軸で傾向コメントを表示
- 第1フェーズ: 静的テキストマッピング表示
- 第2フェーズ以降: AIによる個別分析コメント生成を検討

---

### 3.4 メンバー探索・可視化

#### 3.4.1 スキル検索（管理者・全ユーザー）

- スキル名・言語名・資格名・ドメインでの横断検索
- 複数条件のAND/OR検索
- 検索結果一覧でのスキルサマリー表示

#### 3.4.2 スキルマップ（管理者向け）

- 部署別・スキル別のヒートマップ表示
- 組織全体のスキル分布グラフ
- スキルギャップ分析（必要スキルとの比較。必要スキルは管理者が設定）
- CSV エクスポート機能

#### 3.4.3 相性・共通点マッチング（一般エンジニア向け）

- 「同じ技術スタックを使っている人」の推薦表示
- 「同じ資格を持っている人」の一覧
- 「同じ興味タグを持っている人」の表示
- ストレングスファインダー / MBTIが同じ or 相性の良いタイプの表示（任意登録者のみ）

#### 3.4.4 シニアエンジニア相談窓口

- シニアエンジニアが「相談受付中」フラグを設定可能
- 受付中の相談分野（技術領域・キャリアなど）をタグで設定
- 一覧ページに相談受付中のシニアエンジニアを表示
- 相談リクエスト機能（社内チャットツール連携 or メール送信。第2フェーズ以降）

---

### 3.5 学習ログ・活動記録

#### 3.5.1 ログ入力

ユーザーが日々の学習・活動を簡単に記録できる仕組みを提供する。

| 項目 | 必須 | 説明 |
|---|---|---|
| 活動カテゴリ | ○ | 読書 / 資格勉強 / 個人開発 / 勉強会参加 / OJT / その他 |
| タイトル | ○ | 活動の内容（例：「Rust入門書を読んだ」） |
| 活動時間（分） | ○ | 15分単位での入力を推奨 |
| 活動日 | ○ | デフォルトは当日 |
| メモ | - | 自由記述（任意・300文字以内） |
| タグ | - | 技術名・資格名など |

- モバイル対応のシンプルなUI（スマホからの入力を考慮）
- ホーム画面に「今日の記録」クイック入力ウィジェットを配置

#### 3.5.2 ログ集計・可視化

- **累計時間表示**: カテゴリ別・全体の累計時間をダッシュボードに表示
- **週間・月間・年間カレンダーヒートマップ**: GitHubのコントリビューショングラフ風の活動カレンダー
- **連続記録日数（ストリーク）**: 連続何日記録しているかを表示
- **カテゴリ別円グラフ**: 活動時間の内訳

## 4. 非機能要件

### 4.1 パフォーマンス

- 検索・一覧表示: 2秒以内のレスポンス
- ページ初期表示: 3秒以内

### 4.2 可用性

- 稼働率: 99.5%以上（社内システムのため）
- メンテナンス時間帯: 毎週日曜 深夜帯（通知付き）

### 4.3 セキュリティ

- HTTPS通信の強制
- パスワードのハッシュ化（bcrypt）
- SQLインジェクション・XSS対策
- ロールベースアクセス制御（RBAC）
- 個人情報（MBTI・ストレングスファインダー）の公開範囲をユーザーが制御可能
- ログイン失敗の連続試行によるアカウントロック

### 4.4 スケーラビリティ

- 初期想定ユーザー数: 50〜200名
- 将来的な拡張を想定したAPIファーストの設計

### 4.5 アクセシビリティ

- モバイルブラウザ対応（スマホからのログ入力を考慮）
- レスポンシブデザイン

## 6. データモデル概要

### 主要エンティティ

```
User
├── id, name, email, role, department, grade, join_year
├── avatar_url, bio, github_account
├── Skills (1:N) - language, framework, infra, level
├── Certifications (1:N) - name, acquired_at, expiry_at
├── PersonalityProfile (1:1)
│   ├── strengths_top5 (JSON Array)
│   ├── mbti_type
│   └── visibility_setting
├── LearningLogs (1:N)
│   ├── category, title, duration_minutes, logged_at, memo
│   └── tags (M:N)
├── Badges (M:N) - earned_at
└── InterestTags (M:N)
```

## 9. 用語定義

| 用語 | 説明 |
|---|---|
| ストレングスファインダー | Gallup社の強み診断ツール（CliftonStrengths）。34資質のうちTOP5を確認できる |
