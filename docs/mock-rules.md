# TalentHub モック開発ルール

**バージョン**: 1.0.0
**作成日**: 2026-04-17

---

## 1. モックの目的と位置付け

本モックは**ステークホルダーとのイメージすり合わせ**を目的とした動作確認用プロトタイプです。

- ビジネスロジックの正確な実装よりも**UIの見た目・操作感の確認**を優先する
- 確認・合意したデザインは `DESIGN.md` に反映し、**実装フェーズの設計資産として継承**する
- モックで見えた課題・改善点はこのドキュメントの「課題ログ」セクションに記録する

## 3. モックの起動方法

ビルド不要。ブラウザで直接開くだけで動作します。

```bash

open mock/index.html

# または VS Code の Live Server 拡張などで開く
```

**推奨ブラウザ**: Google Chrome / Microsoft Edge（最新版）

## 4. データ管理ルール

### 4.1 データの保存先

すべてのデータは**ブラウザの `localStorage`** に保存されます。

| `localStorage` キー | 内容 |
|---|---|
| `th_users` | 全ユーザー情報（JSON配列） |
| `th_logs` | 全学習ログ（JSON配列） |
| `th_current_user_id` | ログイン中のユーザーID |

### 4.2 初期データ（シードデータ）

### 4.3 データのリセット方法

```javascript
// ブラウザのコンソールで実行

location.reload();
```

または、ページ上の「データリセット」ボタン（開発用フッターエリア）から実行可能。

### 4.4 ユーザー情報の更新

- 学習ログ入力から記録 → `th_logs` に即時保存
- ページリロード後も変更は維持される

## 5. 認証について（モック専用ルール）

モックでは **本物のMicrosoft SSOは使用しない**。

- ログイン画面でどんな内容を入力しても「ログイン」ボタンで遷移可能
- ログイン画面にある「デモロール選択」でログインするロールを切り替え可能
  - `admin`: 管理者ダッシュボード・スキルマップ・ユーザー管理が表示される
  - `senior`: 相談受付フラグ設定が可能
  - `engineer`: 一般ユーザー

## 6. 画面追加手順

新しい画面を追加する場合は以下の手順で行う。

### Step 1: 画面IDを決める

`requirements.md` の画面一覧（セクション5）を参照し、未実装の画面IDを使用する。
（例: `S09` バッジ一覧画面）

### Step 2: HTMLセクションを追加

`mock/index.html` の `<!-- SCREENS -->` コメント以降に新しい `<div>` を追加する。

```html
<!-- ================================
  S09: バッジ一覧画面
================================ -->
<div x-show="screen === 'badges'" class="screen-transition p-6">
  <h1 class="text-2xl font-bold text-gray-900 mb-6">バッジ一覧</h1>
  <!-- 画面コンテンツ -->
</div>
```

### Step 3: サイドバーにナビゲーションを追加

`<!-- SIDEBAR -->` セクションに `sidebar-item` を追加する。

```html
<div class="sidebar-item" :class="{ active: screen === 'badges' }"
     @click="navigate('badges')">
  <!-- アイコン SVG -->
  <span>バッジ</span>
</div>
```

### Step 4: Alpine.js の `navigate()` に対応を追加

必要であれば `navigate(screenName)` メソッドにチャート初期化などの処理を追加する。

## 7. DESIGN.md 更新ルール（重要）

**モックで新しいデザインパターンを導入・変更した場合は、必ず `DESIGN.md` を更新すること。**

### 更新が必要なタイミング

| ケース | 更新箇所 |
|---|---|
| 新しい色を使った | カラーパレットに追記 |
| 新しいコンポーネントを作った | コンポーネントパターンに追記 |
| 既存のコンポーネントのスタイルを変更した | 該当セクションを更新 |
| 新しいアイコンを割り当てた | アイコン割り当て表に追記 |
| レイアウトルールを変えた | スペーシング・レイアウトを更新 |
| アニメーションを追加した | アニメーション・トランジションに追記 |

### 更新手順

1. `DESIGN.md` の該当セクションを編集
2. 変更履歴テーブルに日付・バージョン・変更内容を追記

```markdown
| 2026-04-25 | 1.1.0 | メンバーカードに「共通点ハイライト」スタイルを追加 |
```

3. バージョン番号のルール:
   - パッチ (`x.x.1`): 小さな追記・修正
   - マイナー (`x.1.0`): 新コンポーネント追加・既存変更
   - メジャー (`2.0.0`): デザインの大幅刷新

## 8. コーディング規約

### HTML / Alpine.js

- `x-show` で画面表示を制御する（`x-if` は避ける。DOMを保持することでチャートが壊れにくい）
- 各画面には `screen-transition` クラスを付与してフェードイン
- IDは `screen-{名前}` の形式（例: `id="screen-dashboard"`）

### データアクセス

- ユーザー情報の参照は常に `this.users.find(u => u.id === xxx)` 形式
- 直接配列インデックスでのアクセスはしない（順序変更に脆い）

### 命名規則

| 種別 | 規則 | 例 |
|---|---|---|
| 画面名 | kebab-case | `my-profile`, `learning-log` |
| ユーザーID | `u` + 3桁ゼロ埋め | `u001`, `u002` |
| スキルID | `s` + 3桁ゼロ埋め | `s001`, `s002` |
| ログID | `log_` + タイムスタンプ | `log_1713360000000` |
| バッジコード | スネークケース | `hours_100`, `certs_3` |

### Alpine.js メソッド命名

| 種別 | 規則 | 例 |
|---|---|---|
| 画面遷移 | `navigate(screen)` | `navigate('dashboard')` |
| データ取得 | `get` + 名詞 | `getTotalMinutes(userId)` |
| データ更新 | 動詞 + 名詞 | `saveProfile()`, `addLog()` |
| 表示ヘルパー | `format` + 名詞 | `formatMinutes(min)` |

## 9. モックのスコープ外（実装しないもの）

以下は本モックでは実装しない（実際の開発フェーズで対応）:

- Microsoft SSO の実際の認証フロー
- サーバーサイドAPI・データベース
- ファイルアップロード（アバター画像）の実際の保存
- メール・Slack通知
- CSV エクスポートの実際のファイル出力
- 管理者によるユーザー招待フロー
